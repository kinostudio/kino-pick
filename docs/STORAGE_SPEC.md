# Cloudflare storage integration status

CF-03c3 integrates the trusted Node adapter with local D1/R2 jobs. Before derivative writes it atomically reserves16MiB at workspace and primary node; fixed scoped keys and create-only checksum-bound puts are reused across retries. Unknown writes, lease expiry and review preserve reservations. Only both verified outputs permit atomic assets/audit/actual-byte conversion; private gallery streams those exact slots. Local manifests have no authority.0013 is additive, no legacy backfill; recovery and review-held capacity restrictions are in PROCESSING_PIPELINE.md. Production runner/multi-node processing/live resources remain gates and all private/default-OFF protections remain.

Original STORAGE_RETENTION.md / PHOTO_VERSIONS.md / GUEST_ACCESS_AUDIT.md remain requirements. New target defaults to a single same-account private R2 node; cross-account routing requires a future explicit administrator control plus terms/billing acknowledgement. No automatic account creation or free-quota stacking is implemented.

Implemented: D1 storage_nodes fields for provider/account/bucket/endpoint/credential_ref/status/priority/quota/used/reserved/reconciliation; one active node guard while multi-account disabled; 9GB internal quota default for new D1 nodes. Node API exposes only operational fields after Owner authorization. No credentials/endpoint/account IDs in that response. Existing PG quotas remain unchanged.

R2StorageAdapter implements the existing StorageAdapter boundary with tenant/project/album prefix validation, conditional immutable puts, scoped HEAD/range/read and bounded buffered IO. fenceIfAbsent conditionally creates a permanent zero-byte marker with upload-session metadata using If-None-Match: *; it never deletes or overwrites an object. The application signer in apps/worker/src/r2-presign.ts is separate from this low-level adapter and is reachable only when the direct-upload feature flag and all R2 signer secrets are present. deleteObject remains disabled while destructive jobs are absent. The adapter is not an authorization service or a full image decoder; completion checks bounded structural image headers/dimensions, which is still not full pixel decoding.

Migration 0009 is a D1 schema migration that adds immutable upload specs, authorization/workflow records, key fences, review flags, photo_versions, photo_assets and completion records, plus immutable guards and quota conversion on verified completion. Migration 0010 is a forward-only D1 schema repair for the early local 0009 draft: it replaces the upload-spec triggers so the immutable upload request payload supplies content type and SHA-256. Migration 0011_photo_scope_integrity.sql adds scoped indexes and guards for photo/version/asset/completion/audit relationships. The local Wrangler D1 is upgraded through early0009, repair0010,0011 and0012; migration 0011 is also covered in an isolated Miniflare upgrade test. None of these migrations has been applied remotely. Retain migration records, do not down-migrate, and use a new forward migration for future repairs. Backup/restore rehearsal through0012 remains pending before any remote migration.

The direct-upload lifecycle is: reserve D1 quota → issue a short-lived exact-length/checksum/MIME/create-once R2 grant → client PUT → inspect R2 HEAD/checksum/MIME and bounded JPEG/PNG/WebP structural headers/dimensions → create immutable original photo/version/asset metadata and convert reserved to used. Header inspection is not a full image decode. Invalid content becomes needs_review, keeps its reservation, and is excluded from automatic expiry; no review-resolution route currently releases it. An authorized reservation can be cancelled or expired only after a winning conditional permanent key fence is recorded in R2 and D1, which prevents late bearer-URL writes; occupied keys remain reserved for retry. Local isolated tests cover these transitions, but DIRECT_UPLOAD_ENABLED defaults to false and is false in all Wrangler environments. The local test override uses synthetic signer values and an isolated R2 binding, so it is not live R2, bucket CORS, remote D1 or browser-to-live-R2 evidence.

The existing product requirements for logical photos, immutable version history, slider/parallel/overlay/diff, annotations/comments and guest per-action events remain. Feature-gated browser batch upload and transient local previews are implemented. Persisted gallery/thumbnail assets, resumable/multipart uploads, version replacement/matching, trusted server decoding/diff processing and cross-node moves remain future slices. Cross-node moves must remain copy → verify size/hash → atomic metadata switch → delayed source cleanup, with retry/compensation; provider-compatible S3 and administrative multi-node enablement remain extension gates. Production defaults stay one private node with multi-account routing disabled.

Cron performs upload reservation expiry and records a retention dry-run observation. Real album eligibility/preview, minimum retention, legal hold/pinned/active processing guards, quota 80→65%, 30-day valid-human viewing, locks, retry jobs and physical deletion remain pending. No retention bytes are claimed reclaimed. See DEPLOYMENT.md for exact local commands and recovery/fee boundaries.

## CF-03c1 processing boundary

Browser createImageBitmap decodes a bounded file and re-encodes a transient320px JPEG preview. Local blobs are not R2 assets or durable thumbnails and do not consume storage quota. Only verified original bytes convert reservation to used quota. Future derivatives must reserve/count all bytes and preserve immutable keys/scope/audit/idempotency.

0012 stores encoded dimensions while retaining historical NULL values. Both init/authorize require enabled signing. Worker reads <=256KiB headers; it does not independently decode pixels or prove decompression-bomb safety. No Cloudflare Images/Queues paid binding enabled. All upload flags remain false; intercepted S3-to-Miniflare tests are not live CORS proof.
