# Cloudflare Images adapter

`packages/image-processing/src/cloudflare-images.ts` implements the existing `ImageProcessingAdapter` using the native Images binding. It imports no Sharp/Node native decoder, accepts no source URL and owns no storage, queue, lease, retry or quota mutation. Inject the binding per request/job; do not retain request bindings globally.

Recipe: `cloudflare-images-jpeg-82-v1`, deliberately distinct from immutable `local-sharp-0.35.5-v1`. Current D1 jobs/outbox and durable runner still accept only the old recipe. This module is NOT registered in the product Worker and does not authorize changing job provenance. Source-only implementation; no schema changes this slice.

Input: strict existing identity contract, snapshot before first await, exact byte count/SHA256, bounded JPEG/PNG/WebP raw header dimensions,80M pixels and32768-side guards, reused animation/multi-image rejection plus provider inspection. Internal source memory ceiling16MiB is an application choice, not a Cloudflare service-limit claim. Existing64MiB upload admission is not automatically supported by this recipe: later admission/processing configuration must handle that mismatch explicitly before activation.

Output: sequential320/2048 scale-down JPEG quality82, opaque white background, no animation; response status/MIME/declared length and streaming8MiB limit, overflow cancellation; strip EXIF/XMP/ICC/IPTC/COM across baseline/progressive scans, preserve pixel interpretation APP0/APP14; validate stripped output headers and provider info, bounds, size/hash. A failed provider call returns a fixed error code without embedding its raw error or retrying. Durable integration must own retry/backoff/quota accounting and preserve two-output atomic publication. The binding is a trusted encoder; info is not an independent full pixel decoder.

Official API references: [Images binding](https://developers.cloudflare.com/images/optimization/binding/), [Workers best practices](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/). Retrieved2026-10-31; current generated Worker binding types were used. No new paid plan, quota guarantee or billing claim.
