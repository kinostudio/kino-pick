## Architecture decision

- TypeScript strict; pnpm Monorepo。`apps/web` Next.js App Router；`apps/worker` R2 image delivery / image jobs；`packages/db` migrations / repository；`packages/domain` business rules；`packages/contracts` zod API schemas；`packages/ui` shared UI；`packages/storage` storage abstraction。
- Supabase Postgres 與 Auth（Google / GitHub OAuth；同一 user 可綁一或兩種來源），workspace/tenant-aware RLS + API service authorization。
- Cloudflare R2 兩個私人 buckets：originals 與 derivatives；原圖／成品和 thumbnail／preview 分開設定存續政策。
- 產生縮圖與浮水印可使用支援的 Cloudflare Images/Workers pipeline；如果影像格式或運算配額不支援，另以隔離背景處理容器／job runner 處理（需記錄 ADR，不能假設 Workers 可支援任意 RAW）。

## CF-03b historical upload backend boundary (superseded by CF-03c1 below)

The Worker reserves bytes in D1 before transfer, then issues a short-lived create-once R2 PUT scoped to a server-generated private object key. Authorization binds expected Content-Length, Content-Type, SHA-256 checksum and `If-None-Match: *`; the key and signer credentials never enter the response. Completion verifies the object size, stored MIME, R2 checksum and image signature before an atomic D1 transaction creates a logical photo, immutable first version and original asset, converts reserved to used bytes, records a result snapshot and appends audit.

A signed URL is a reusable bearer credential. Cancel/expiry therefore attempts a conditional zero-byte fence on that same key first; only a persisted fence permits reservation release. If an object already occupies the key or fencing fails, capacity remains reserved for review/reconciliation. Invalid content enters `needs_review` and retains its reservation. Local workerd/D1/R2 tests cover this design; direct upload is disabled in local/staging/production configs, and real R2 checksum/CORS/browser behavior remains unverified. No upload UI, thumbnail, gallery, multipart/resume or image decoder is included. Automatic retention deletion remains OFF.

Browser navigation and same-origin fetches use the same Worker host and Better Auth Owner cookie; GET /api/v1/me gates the UI, while the server remains authoritative for every read/write. D1 currently supports the surfaced workspace/project/album metadata operations, CAS/audit, album protection and reversible empty-content archive. No photos, guest sessions, upload, version, delivery, member roles, or full retention UI is implied. Existing Next/Supabase is preserved; the separate vinext worktree remains hosting evidence only.
