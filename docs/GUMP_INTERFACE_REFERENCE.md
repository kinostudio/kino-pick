# Gump 相簿與分享介面參考（2026-10-29）

本紀錄依使用者提供的三張圖片及其 Gump 相簿、分享彈窗、編輯相簿、照片頁與建立相簿畫面的實際瀏覽觀察。僅供 Kino Pick 自行設計與實作；沒有儲存 Gump 相簿設定、建立相簿、傳送分享或修改照片。

## 已實際觀察

- 相簿管理：客戶名稱／相簿名稱、封面、照片數、喜愛、攝影師推薦、客戶選取數／上限、複製已選檔名；資料夾、精選、多選、下載及排序入口。
- 建立相簿：客戶名稱、相簿名稱、可選照片夾；可展開進階設定。截圖另顯示下載全部／已選／否、協作、喜愛、客戶挑選及上限、繪圖評論、密碼、評價與使用同意。
- 編輯畫面實際展開：封面與焦點、版面、標題、下載與協作、喜愛、選圖上限、自動鎖定、繪圖評論、密碼、客戶評價、照片使用同意。未儲存任何變更。
- 分享彈窗：相簿與子相簿入口、到期狀態、連結、密碼保護與複製，另有 WhatsApp、LINE、QR 等分享入口。使用者提供截圖顯示到期與密碼開關；這次未切換或測試其是否立即儲存。
- 照片頁：照片居中、左右導航、底部縮圖、推薦、置頂、版本、繪圖、評論、變更紀錄、檔案資訊。實際展開變更紀錄，看到 Version 1 Uploaded 及時間。
- 前端頁面實際觀察到 /_next/static/chunks 與 Turbopack 資源，以及 Muuri 0.9.5；可判斷載入 Next.js 相關前端資源，不能據此推斷後端資料模型、授權、API 或儲存實作。

## Kino Pick 對應方向

1. 專案／相簿以清楚的客戶、相簿名稱和封面摘要呈現；進階設定按用途分組，預設簡潔。
2. 分享以現有邀請機制為核心：單獨設定查看、下載、選取、星等、收藏、標籤、註記和留言權限，並顯示密碼模式及有效期限。保留一次性憑證顯示、精確授權與撤銷機制，不用可猜測名稱當存取憑證。
3. 相片檢視以大圖、縮圖列與可收合工具區支援版本、評論、註記和歷史；維持既有私有物件、版本綁定、可及性與手機版操作。
4. Gump 的自由畫筆、攝影師端前後對比、評價、照片使用同意、子相簿與已選下載等需逐項核對並完成服務端契約及驗收後才呈現為可用；不增加無效按鈕。
5. 先保留本專案既有雙 OAuth、獨立訪客權限、不可變版本、審計與安全清理設計；參考不代表逐項照搬或推斷對方保護措施。
