## M3d implementation refinement — retain legacy namespace witnesses

The implementation uses immutable owner_external_intents for the two R2-backed operations and transactional namespace guards on every existing Owner writer. Existing D1 command ledgers remain the authority for already-used actor/request IDs; they are not rewritten or backfilled into a new canonical registry. This supersedes the all-writers/backfill proposal in steps1–3 below.

A new external claim atomically checks all legacy Owner ledgers before winning actor/request. Conversely, every D1 writer atomically checks claims before committing; only the exact bound upload.cancelled or processing-review finalizer may consume its own claim. Thus either the D1 command wins first and the claim conflicts before R2, or the claim wins first and a competing D1 command rolls back. This closes the cross-ledger race while preserving legitimate workspace and selection-policy alias witnesses. It is not a read-only preflight.

Claims fix target keys/node/scope/lease internally and append owner.external_intent_claimed once with actor/session/request/UTC correlation; no keys/secrets in audit payloads. They never release quota or certify an R2 result by themselves. Existing completed commands replay before attempting a new claim. ## Required linearization point

A durable claim must win the actor/request namespace before an external effect. The claim fixes operation, canonical payload, workspace/project/album and exact upload session or processing job/lease epoch. Current Owner/session/resource authority is checked in the claim transaction and again before resuming/finalizing. Identical intent may recover the same claim in a later valid session; a different operation/payload/target must conflict before R2 is touched. R2 outcomes remain idempotent at immutable target keys. Unknown results retain the claim and held quota. A successful final transaction records command/result/audit, state and quota effects against the same claim.

A read-only preflight is useful diagnostics, but cannot replace this claim: another writer may take the ID between the read and an R2 call. Do not claim race safety from an expanded SELECT list.
