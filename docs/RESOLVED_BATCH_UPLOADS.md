## Admission and correctness

Every upload reservation advances the album matching change sequence. Consequently the queue must obtain a fresh preview for each file; it must not capture an entire batch against one sequence. First delivery serializes preview, explicit decision, durable intent, reservation and completion before admitting the next file. Preparation and transfers are bounded. Later concurrency may be added only with evidence that pending names, target heads and policy changes preserve these semantics.

The queue approval captures project revision, versioning mode and optional immutable matching profile/rule revision. Policy changes pause unstarted items for explicit review. Each item's preview supplies its own current album sequence. Ambiguity, missing index coverage, pending matches and changed version targets require review; they never silently become new photos. Assisted targets remain explicit per-file choices. A definitive server rejection may allow an explicitly requested fresh decision; an unknown result always retains the original IDs, body and target.

## Durable metadata

The existing resolved journal is deliberately one item and64KiB. Do not raise that array cap or reuse ordinary upload init/recovery for version targets. The new queue uses a small manifest and independently validated per-file records, scoped by actor, workspace, project, album and queue UUID. Initial documented bound is1,000 file descriptors, with24-row UI/storage pages. Descriptors are metadata; cryptographic fingerprints are prepared and confirmed before each captured intent. File bytes, File/Blob objects, local preview URLs, OAuth credentials and signed upload URLs must never enter this store.

Before the first mutation for an item, commit its exact reservation body, distinct reservation/authorize/completion UUIDs, fingerprint and selected target. Persistence success means the storage transaction committed, not merely that an individual write request succeeded. An aborted/quota-failed transaction prevents network mutation. Every captured record reuses the current single-file journal's strict scope/fingerprint/target checks. Unknown or expired/corrupt records remain visible as blocked recovery state and are not silently erased.

The manifest has a revision for compare-and-swap updates. Item IDs/ordinals and captured bodies are immutable; completion changes/removes only its own row, never other items. Cross-tab writers require transactional authority/lease coordination before admission. Identity/session replacement suspends processing and clears transient private UI; reauthorization must preserve fixed intents. Same-actor new sessions require explicit continuation under current server authority, never replacement UUIDs. Session IDs are opaque metadata, not authentication credentials; actual APIs continue to authorize every operation.
