## Cron and storage limits

Staging/production Cron is configured every five minutes. Each run expires unissued reservations directly and attempts to expire authorized reservations only after an atomic, permanent R2 key fence; an occupied or unconfirmed key leaves counters reserved for retry. A successful fence releases reserved bytes and appends the upload fence/expiry audit event; it never deletes an R2 object. The request-time GET path only expires reservations that have no authorization. Retention still does not select candidates, reconcile bytes, preview deletions or delete anything. Local scheduled behavior is covered by isolated workerd/D1 tests; no remote Cron has run. Automatic deletion remains false and `dry_run` true in both configuration and D1 constraints.

Default new D1 node quota is 9,000,000,000 internal bytes from the addendum; existing PostgreSQL 8GB settings are not rewritten. This is not an official free limit or a zero-bill promise. Wrangler declares one same-account private R2 binding per environment and multi-account routing is false; those bindings do not establish that remote buckets exist or that live transfers work. `storage_nodes` stores credential_ref only; no S3 secret is stored in D1/frontend. The CF-03b signer signs exact length, MIME, SHA-256, create-once and scoped object key; completion validates R2 size/checksum/MIME and bounded structural headers/dimensions and creates immutable photo/version/asset metadata. These behaviors are locally tested only. `DIRECT_UPLOAD_ENABLED` remains false in local, staging and production Wrangler vars; test-only Miniflare overrides use synthetic credentials. Live R2 signer credentials, bucket CORS, remote D1, actual browser-to-live-R2 transfer and production Cron remain not_checked. Thumbnail/preview processing, resumable/multipart upload and cross-node moves remain pending. Successful uploads now use a real Chromium-decodable PNG. Header-only/corrupt fixtures are negative cases; binary storage tests are not full processing acceptance.

Verify current official [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/), [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/), [R2 pricing](https://developers.cloudflare.com/r2/pricing/) and [Queues pricing](https://developers.cloudflare.com/queues/platform/pricing/) plus applicable Cloudflare terms before resource creation or any cross-account policy. Quotas, CPU/memory, operations and monthly storage accounting are separate costs. Browser/local thumbnail generation remains the initial direction; no large-image decoding/heatmap is assumed to fit Free Workers.

### CF-03b direct-upload boundary

The implementation follows current [R2 presigned URL behavior](https://developers.cloudflare.com/r2/api/s3/presigned-urls/): a PUT URL is a bearer credential and remains reusable until expiry. The signer uses R2's atomic [`If-None-Match: *` conditional PutObject](https://developers.cloudflare.com/r2/api/s3/extensions/) for a generated create-once key and binds exact `Content-Length`, content type and SHA-256 checksum. Cancellation and authorized expiry first write a permanent fence marker at that key; the D1 reservation is released only after the fence wins. This closes the late-write race without deleting customer objects. Configure the bucket's [browser CORS policy](https://developers.cloudflare.com/r2/buckets/cors/) for the exact app origin and signed request/response headers before enabling the feature. Chromium/local Blob PUT behavior is tested, but live bucket CORS and browser-to-live-R2 transfer are not.

R2's current [single-upload object limit](https://developers.cloudflare.com/r2/platform/limits/) is 5 GiB; the product schema enforces `5,363,466,240` bytes (5 GiB minus 5 MiB) for this single-part slice. Multipart/resumable upload is a later slice. `DIRECT_UPLOAD_ENABLED` must remain false until real signer secrets, bucket CORS, remote D1/R2, OAuth and a live end-to-end transfer have been separately verified. Never put R2 secrets in D1, source control or browser responses.
