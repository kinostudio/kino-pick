# Retention planning foundation

This is the first safety prerequisite for M4 retention. The planner is a deterministic pure calculation over an explicit workspace snapshot. It must not perform R2/SQL writes,delete files,alter quota ledgers,renew human-view timestamps or enable Cron execution. Automatic deletion remains OFF;all output is dry-run and byte figures are estimates.

The source snapshot must include complete same-workspace album inventory,confirmed/reserved/quota bytes and metric health/time,actual asset byte/count/version totals,explicit cleanup opt-in (`cleanupAllowed`),protection and preservation requests (`preservationRequested=true` always excludes),workflow/upload/processing/delivery activity,reference verification and genuine human-view/state-change timestamps. The future D1 adapter must gather these witnesses;absent evidence must never be replaced by metadata updated_at or a guess that an album is idle.

Policies cover inactivity (default30 days),minimum age(default7 days),pressure trigger80% / estimated target65%,oldest-created or least-recently-viewed sorting,and bounded albums/bytes per run. Default policy is disabled. Never-viewed baseline is published_at or created_at;last valid human view can extend that baseline,ordinary uploads/metadata cannot. Capacity includes reservations but reservations and permanent fences are never estimated as reclaimed assets. Numeric inputs must be nonnegative safe integers,and integer threshold comparisons must avoid float boundary errors.

Pinned/legal-hold/project-protected/excluded/requested-retention/busy/unverified-reference/deleting albums are excluded. Recent human viewing or state change within15 minutes excludes a candidate. Unhealthy or stale metrics and incomplete inventory block planning. Both policies deduplicate albums and retain inactivity reasons;pressure-only additions stop at the estimated65% target or limits. No candidate means existing data is retained;an estimate never releases real capacity or overrides upload admission protection.
