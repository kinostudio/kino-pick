## Scope and authorization

GET /api/v1/owner-history/capabilities reports the independent OWNER_HISTORY_ENABLED gate. It defaults false in local/staging/production and is hard-local. GET /api/v1/workspaces/:workspaceId/history requires the current enabled Owner, live opaque Owner session, owned workspace and matching X-Kino-Expected-Actor. Each data query repeats current D1 authorization; every page and export chunk revalidates ownership. Expired/revoked Guest grants and archived resources remain historical evidence, never current Guest access grants. Owner authentication events with no workspace and global Cron observations remain outside this workspace timeline; do not invent a workspace association for them.

Optional exact filters: projectId,albumId,photoId,versionId,inviteId,actorType(user/guest/system),actorId,action,from,to. All resource filters must belong to this workspace; physically removed resources need an immutable workspace audit witness and cannot override a currently existing foreign resource. Supplied resource IDs retain exact SQLite case. Unknown/duplicate query parameters are rejected. UTC from is inclusive and to exclusive; at most millisecond precision, normalized to UTC ISO milliseconds before comparison. The range must increase. Read operations append no audit, image access or retention activity.

Guest invitation attribution uses immutable historical sessions/identities; Owner comment/annotation/processing uses immutable change witnesses. Revocation uses the original command, exports use the referenced immutable submission, and selection reopen reconstructs and exactly validates the canonical retained event ID/Guest/invite/album/round. A shared-review Owner event may affect up to24 invitations: relatedInviteIds preserves all sealed owned memberships, while inviteId remains nullable rather than arbitrarily choosing a member. Invitation filters match these explicit relationships; sharing one invitation never grants access to other workspace history.

## Snapshot and projection

The initial snapshot uses a workspace-prefix index with implicit SQLite rowid order for a bounded last-row seek. Later authority checks never recompute a history-wide MAX. Fixed24-event pages sort by occurredAt DESC,eventId DESC. A signed15-minute snapshot fixes the maximum audit rowid before paging/export, excluding later appends even when backdated. The versioned HMAC namespace binds purpose,Owner,workspace,all canonical filters,high rowid,position and expiry. Cursor and snapshot purposes are not interchangeable. Pages return the same snapshotToken; nextCursor additionally binds the last UTC/event position. Resource/current authority is never inferred from a token alone.

Every event retains its original event ID,UTC,actor type/ID,workspace/project/album/photo/version,opaque session IDs and request ID. Related invitations are derived from immutable witnesses. Display labels enrich the identity using retained Guest names or the current Owner profile; they are not a claim that an old event captured an original profile name. The immutable event IDs and before/after values remain authoritative. These are Owner-only metadata; session IDs are not cookies/tokens. Before/after projection is explicit by actual audit action, bounded and recursively stripped of unrecognized fields. Known safe fields include state/revisions,selection/rating/favorite/tag,comment body,annotation geometry/style and Owner processing. Secrets,hashes,raw command payloads,storage keys,signed URLs and OAuth credentials are excluded. Unknown actions have details.status=omitted and null before/after; malformed recognized details have invalid and null values. No raw-JSON fallback. Browser rendering uses escaped text.

## Streaming export and truthful audit

POST /api/v1/workspaces/:workspaceId/history/export requires exact Origin,matching header/body expectedOwnerId,strict JSON,no query and a12288-byte body limit. Body is expectedOwnerId,snapshotToken,format(csv/json). Each explicit attempt gets a NEW server generation/request UUID; this endpoint does not promise exact-command replay. The supplied list snapshot fixes the complete filtered export, not just loaded UI pages. The server processes bounded24-event chunks with backpressure and current Owner checks, without loading all events in memory.

owner_history.export_started is appended before streaming. owner_history.export_completed is appended only after the complete snapshot is generated and authorization still holds, before the final successful stream close. Count/format/generation/snapshot rowid/filters are metadata; no full event content or signing token is audited. Audit failure errors the stream; an early cancellation or mid-stream authority loss must not manufacture completion. Server completion does not prove client receipt. A transport may prefetch and finish generation before a client cancellation; cancellation tests must control the repository stream before generation finishes rather than retroactively forbid a valid completed event. The separate local/synthetic-only test Worker uses the actual repository/D1 in-process stream for deterministic cancellation and session-expiry checks,while HTTP/browser failure/no-file checks remain separate; it is never mounted in the deployable API. Export audit events are newer than the snapshot and therefore cannot recursively enter their own file.

CSV quotes every field and neutralizes spreadsheet formula prefixes, including whitespace/control prefixes. JSON ends with complete=true and the generated count. The UI waits for the entire body and rechecks current identity before creating a downloadable Blob; it clears private state on blur/hidden/auth denial/identity change and ignores late generations. Its64MiB client memory guard rejects explicitly instead of silently truncating; larger exports need a future authorized artifact/job flow. Expired snapshots require reload and an explicit new export attempt.
