# 產品需求規格 PRD

## 0. 願景與成功標準

KINO Pic 是讓攝影師以最少操作完成「建立專案 → 上傳照片 → 分享挑片 → 客戶註記 → 追蹤精修版本 → 驗收與交付」的平台。UI 應像專業作品集，產品行為像可靠的專案協作系統。優先支援繁體中文與 RWD；往後可 i18n。

初版非目標：AI 生成人像修圖、RAW/PSD 原生雲端編輯、電商結帳、多租戶支付訂閱、即時協作游標。保留擴充接口但不假造完成狀態。

## 1. 角色

- `workspace_owner`：工作空間、成員、配額、刪除政策及所有專案管理。
- `workspace_editor`：依權限管理專案及照片，不可修改全域付費或機密設定。
- `photographer` / `retoucher`：可指定細部權限，處理版本與留言。
- `client_authenticated`：日後 Google/Email 登入的客戶，可見被授權的多專案歷史。
- `guest`：憑 private invite 登入的免註冊客戶，其行為仍需以 guest identity 與 session 記錄。

## 2. 管理端功能（MUST）

- Google / GitHub OAuth（可只綁一種或雙來源共用同一身分）、使用者檔案、workspace，至少支援單人擁有與可擴充成員表。
- Dashboard：全部、草稿、待挑片、精修、待驗收、已交付、已封存、將到期相簿。
- 專案：名稱、說明、封面、客戶、日期、狀態、相簿、下載政策、版本控制開關、挑片模式、挑片數上限、截止、分享設定。
- 照片：拖拉多檔批次上傳、上傳進度、重試、縮圖、預覽、原圖（按權限）、排序、搜尋檔名、批量管理。
- 可建立邀請連結，指定查看/下載/挑片/評等/收藏/標籤/註記/留言等能力的逐項權限。
- 可查看客戶選取清單、動作時間軸、指定版本差異、留言處理狀態，匯出 CSV / 檔名清單。
- 選片提交後可凍結，管理員可在有記錄下重新開啟；交付成品、過期策略與版本追蹤。
- 儲存後台：總量、用量、各相簿估計釋放空間、當前清理規則、dry-run、排除清單、歷史執行紀錄、失敗重試、刪除通知。

## 3. 客戶端功能（MUST）

- 私密邀請連結、可選無密碼／系統產生密碼／攝影師自訂密碼；可設定期限、最大存取次數（可選）、是否允許下載／挑片／評等／收藏／標籤／標註／留言。
- 不用建立 Google 帳號；進入後可填暱稱（如果 owner 要求，可透過 OTP 驗證 Email，避免冒名），建立會話狀態。
- Grid：Masonry/保留原始比例、縮圖尺寸、分頁／虛擬列表、多選、單張放大、方向鍵、篩選「全部/已選/未選/收藏/星等/有留言/有標註」、排序。
- Photo Lightbox：照片、檔名、選取、1–5 星、收藏、標籤、留言、局部圈選註記（具操作權限）、修圖版本、Before/After。
- 自動保存；超額限制後端硬性阻擋並能保留當前操作；提交選片有確認及歷史快照。
- 客戶歷程：依其可存取的專案，查看選取變更時間軸、留言、版本審核及可用成品。無密碼匿名專案僅可查看該邀請的授權範圍；跨專案需額外認證／portfolio token。

## 4. 選片狀態模型（MUST）

`draft -> uploading -> selecting -> submitted -> retouching -> reviewing -> approved -> delivered -> archived`。每一次回到 selecting 必須保留上一輪的提交快照。物件與審核權限隨階段變動；更改狀態要記錄 actor、timestamp、request_id。

## 5. 版本行為（MUST）

- 新增版本只建立新 asset，保留舊版本 bytes（若版本策略設定保留）；可標記最新可見、可手動恢復可見版本；不覆蓋原始內容。
- `same_filename_auto` 須 per album/ project 明確啟用；同專案不同相簿、不同照片不會自動錯配。SHA-256 完全相同時提示重複檔，不產生內容重複版本（除非使用者確認）。
- 自動比對前後版本：滑桿、左右並排、切換閃爍、可選熱區差異。版本完整資料與註記不會在新增版本後消失。

## 6. 日誌歷程（MUST）

對選取/取消、收藏/取消、評分前後值、標籤增減、註記建立/修改/刪除、留言、提交/撤回、下載、開啟/關閉分享、版本操作，保留 append-only event 和 UTC 時間。提供相簿/照片/客戶三種檢視與分頁 CSV 匯出。刪除照片後顯示 tombstone（相片已過期），事件歷史的保存期獨立設定，並支援資料主體刪除需求。

## 7. 非功能需求 / SLO（目標，不代表現已達成）

- 1,000 張照片的相簿可流暢分頁、Lazy Loading；避免一次渲染所有照片 DOM。
- 事件寫入與狀態變更須在同一 DB transaction；重送相同 request_id 不可重複計數。
- 1000 張 JPG 批次上傳允許部分失敗重試；不因單一縮圖工作失敗造成全局故障。
- 所有 destructive jobs 具 dry-run、重試、進度、錯誤紀錄及不可自動刪除防護。
- 支援桌面、平板、手機；主要互動符合鍵盤操作與 WCAG AA 的可操作性目標。

## 8. 優先級

P0：登入、專案相簿、R2 私有直傳、Grid、選取、評等、收藏、邀請存取、事件紀錄、容量估算與安全政策、版本基本管理、提交與交付。
P1：圈選註記、Before/After、最舊相簿自動清理、30 天未瀏覽定時刪除、批量匯出、多人協作。
P2：熱區差異、客製品牌、支付、AI、第三方後製軟體串接。

> 注：使用者明確要求的所有功能須進入完整規格與驗收；P1 表示建置順序，不是取消需求。

## 已交付封存子集合（2026-10-23，完整狀態機仍保留）

僅當前 owner 可將無照片／閒置的草稿或已交付專案、草稿相簿封存，再還原到所存原狀態。封存暫停名稱／新增內容編輯、不刪除、不解除保護、不重設有效瀏覽。已有照片、上傳／挑片／修圖等進行中流程不在此子集合。完整選片狀態模型與提交快照、版本、交付、保留要求不因此省略；須待對應資料模型與交易 gate 完成後擴充。
